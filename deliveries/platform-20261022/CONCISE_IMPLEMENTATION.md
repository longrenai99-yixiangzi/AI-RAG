## 本轮完成

新增 `runtime/app/answer_engine/llm/grounded_concise.py`，复用现有原文单元、来源版本和 `check_source_units` 校验。模型需要返回简短事实、原文单元编号与逐字短引文；后台据此拼装答案与引用，不直接展示未校验的模型全文。

事实须在绑定主证据中找到短引文，并保留原文明示的条件、例外和数值限定。所问项目、明确年份、设计阶段、专兼职、已识别岗位和面积指标分别检查；岗位人数不能替代缺少明确合计的团队总数。短引文有出处，但模型改写不能通过保守文本检查时，展示核对过的短引文，并记录该事实发生了回退。没有实现通用自然语言蕴含判断，不能称为全部语义已自动核实。

`platform_generation.py` 增加 `CONCISE_V1` 协议，继续使用原有冻结请求、单次授权、来源版本复核和消费账本。新增预览不执行模型。原 `SOURCE_UNITS` 协议和历史预览保留；没有把旧批准包转换成新调用授权。请求文件被改动时在调用前拒绝；原始模型内容留本机，截断或过滤结果不进入答复。

生成或验证失败时记录技术失败，避免误报为资料不存在。仍有效的本地结构化要点或原生字段可以带明确标签回退；整章全文摘录不能作为成功回退。来源变化后不显示过期答复及旧引用。失败不自动重试、不增加修复调用；重复和并发批准不能生成第二次调用。

API 增加受限协议字段，默认值保留旧调用兼容；新的工作台预览按钮明确提交简短协议。界面区分简短协议、历史原文单元协议，以及仍未开启日常自动生成的事实。前端改动仅完成构建，未替换当前正在提供服务的文件。

## 验证

本地代码首轮扩展回归380项通过；补充整章回退、原生字段回退与仅设计团队范围四项检查后，公开副本全部384项通过。前端3项检查、TypeScript及工作台构建通过。两套回归存在重合，不能相加，也不代表382个业务问题。

新增检查覆盖短答复与完整引用分离、错误数字与否定、无依据改写回退、伪造单元/引文、条件和例外丢失、跨项目/年度/阶段/岗位/专兼职、团队合计误用、面积字段混用、路径外发拒绝、协议格式与缺口状态、来源变化、异常和截断、重复及并发调用、旧协议兼容。

提示词注入仅验证了请求层把资料作为数据、系统指令明确禁止执行资料内指令；未用真实模型证明对抗效果。模拟响应只证明程序分支行为，不能证明真实模型的选材、简洁程度与完整性。历史旧协议的真实响应也不能当成新协议真实调用验收。

本轮新增真实模型 HTTP 调用为0；未修改原件、既有索引或业务知识发布状态；未重启、切换在线服务。
