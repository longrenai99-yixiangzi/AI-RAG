# 知识库逐步使用手册（公开版，2026-10-12）

这里讲日常怎么用。程序准备工作见[装配说明](PRIVATE_DATA_ASSEMBLY.md)；正式与试用版本见[当前状态](CURRENT_RELEASE_STATE.md)。公开仓库没有你的真实资料，下载源码后不会自动出现本机知识库。

## 1. 先认清正在用哪个页面

1. 本机正式入口是 `http://127.0.0.1:8000/ai`，当前是C版。
2. 最新W版在 `http://127.0.0.1:8022/ai` 试用，已包含V版功能和回答覆盖修复。新功能先到试用页检查，不默认认为正式页已经具备。
3. 看页面的正式/试用提示和版本；打不开或版本不符时保留错误信息，让维护人员检查，不反复改资料。

## 2. 找文件和找正文分开用

1. 想找某类文件，例如“设计任务书”，使用文件搜索。
2. 先看文件名、所属项目和版本，打开匹配的文件。正文里提到任务书的计划、评估文件，应在相关内容中查看。
3. 想了解任务书怎么写，使用正文/知识搜索或问答。看到摘要后打开原文，检查上下段和适用条件。
4. 结果少时先检查项目筛选与年份，不立即认定资料库没有该资料。

## 3. 有具体项目时带上项目背景

1. 进入项目资料，选已经核对归属的项目。
2. 再选择合同与界面、设计计划、任务书或评估等主题。
3. 提问尽量写清对象，如“示例甲项目施工图阶段的交付成果有哪些？”
4. 没有具体项目的通用问题可直接问，如“编制设计任务书要先核哪些输入？”不必硬选项目。
5. 切换项目后检查标题；跨项目比较要明确说出两个项目，不把甲项目的面积、金额或节点当成乙项目事实。

## 4. 判断回答是否够用

1. 先看是否直接回答了所问对象：问公式，应有计算关系；问提交成果，应有清单；问实际完成情况，应有执行记录。
2. 一次问了几件事，就逐件对照。回答一部分时，其余应明确说未核到，不由你猜。
3. 点引用，看原文相邻段落、表格行、日期与版本。制度要求只能说明应当做什么，不能证明已经做完。
4. 历史报告先作为报告记载阅读；“未评估”不等于零分，也不等于合格。
5. 如仍有错误，点纠正，说明“错在哪、应是什么、原件在哪一页或哪一段”。已有反馈不用再填一遍。

## 5. 查看年度与期间记录

1. 选择单位、年份和期间，例如全年或上半年。
2. 打开完整记录与原件，核对指标对象和计量单位。
3. 页面摘录只是入口，不能认为那几项就是全部年度指标。
4. 需要比较时先确认统计口径一致；不能简单用全年减半年推算增长或下半年成果。

## 6. 编任务书草稿

1. 选择项目、阶段和已核对来源。
2. 查看系统带出的骨架、原文依据及待补项。
3. 把你掌握的要求填到用户补充区，和原文分开。
4. 核对设计范围、界面、输入、成果深度、时间及责任。没有依据的数值和日期保持待填。
5. 导出后再按公司程序审核。草稿导出不代表任务书已批准、已下发。

## 7. 把评估缺项交接成工作

1. 打开项目评估交接页，先确认报告版本。
2. 分清原报告问题、资料缺项、未评估和技术建议；不要把四类混成设计缺陷。
3. 对缺内容先登记需要补什么，不要求先证明旧报告的全部判断正确。
4. 有当前资料时补充文件、责任人和拟完成时间；不掌握时留空。
5. 导出交接清单或计划草稿，交给实际责任人核对；系统不自动确认整改已经完成。

## 8. 做方案比选准备

1. 选择同一对象确实存在的备选方案；不同工程部位不能凑成两个方案。
2. 看原报告建议及其条件，确认当前是否仍适用。
3. 分别填写约束、费用、工期和依据，说明费用是否含税、是否包含同一范围及同一计量基础。
4. 没拿到资料就留空；“0”表示确认为零，不表示不知道。
5. 导出缺资料清单先补齐，再由专业人员判断。系统不会凭便宜或时间短自动批准最优方案。

## 9. 看反馈与保护资料

1. 反馈页区分业务反馈、技术检查和未分类历史记录。
2. “修复已发布，待业务复核”表示程序已处理，仍需要实际业务确认，不等于你已验收。
3. 原件保持只读；清理磁盘前避开运行状态、固定包和验证记录。
4. 新版本要上正式页时，维护人员先给出具体版本、核验结果与回退方法，再按已有授权范围执行。

暂未完成的内容和旧回归差异见[下一步工作](NEXT_WORK_STATUS.md)。发现问题先保留问题、引用与版本，不把“没有搜到”直接当成“原件没有”。
