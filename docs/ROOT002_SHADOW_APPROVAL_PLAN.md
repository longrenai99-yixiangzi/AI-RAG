## 6. Shadow 导入顺序建议

### 第 0 步：审批与清单冻结

- 确认 Root-002 Owner；
- 确认首批子目录和文件白名单；
- 生成审批快照；
- 保存 path、size、mtime、sha256；
- 禁止直接扫描整个 `D:\工作\二公司技术部`。

### 第 1 步：设计管理资料

- 导入 2026 设计与技术工作计划、责任状和示范项目相关文件；
- 先处理 PDF/DOCX 正文可确认的文件；
- 登记页和外部链接分别记录，不混为同一 Document；
- 只生成 Shadow staging。

### 第 2 步：设计服务台账

- 只读打开 XLSX；
- 逐 Sheet 统计有效 Sheet、表头、行列范围和版本；
- 保存行列位置；
- 不把个人信息或无关管理字段送入回答上下文；
- 通过一致性检查后进入 Shadow 候选。

### 第 3 步：新洲星谷/应城智汇港策划评审

- 优先验证价值创造清单 XLSX；
- 重点检查外部文件是否存在、是否属于 Root-002；
- `.docm` 暂不自动解析；
- 记录文件版本和人工批准结果。

### 第 4 步：设计复盘

- 只导入已归档、已确认的设计管理复盘；
- 按项目和日期分批；
- 检查与制度/指南的角色区分；
- 复盘文件只作为案例/方法证据，不自动作为制度。

### 第 5 步：Shadow 对账

- Document 数量；
- SourceBlock 数量；
- Chunk 数量；
- Embedding 数量；
- Qdrant point 数量；
- sha256 和 Chunk ID 一致性；
- Citation 位置完整性；
- 失败回滚和待审批清单。

## 7. 审批后 TASK-016C-2 实施方案

TASK-016C-2 只在 Root-002 子目录审批通过后执行：

1. 读取 Root Policy 和审批白名单；
2. 拍摄 Root-002 文件清单快照；
3. 对批准文件执行只读 Source Resolver；
4. 生成 `knowledge_root_id=Root-002` 的 SourceRecord；
5. 运行 PDF/DOCX/XLSX/PPTX/Markdown Loader；
6. 生成 SourceBlock、Chunk 和 Metadata staging；
7. 在独立 Shadow collection 验证；
8. 对账 Chunk、Embedding、Qdrant payload 和 Citation；
9. 输出失败、缺失、重复、版本冲突和敏感文件报告；
10. 业务负责人确认后，再决定是否进入后续正式发布设计。

TASK-016C-2 不得默认修改正式 Retriever、8000 服务或正式 Qdrant。

## 8. 设计结论

Root-002 不应整体批准。首批应以 P0 白名单方式优先覆盖：

1. 2026 设计管理资料；
2. 2026 设计服务台账；
3. 新洲星谷和应城智汇港概算及策划评审资料；
4. 已归档设计复盘资料。

审批状态在本任务结束后仍为设计建议，不代表已经批准读取或导入。
