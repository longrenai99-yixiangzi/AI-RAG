## 5. PDF 与扫描件判断

### 5.1 判断方法

使用当前 V1 虚拟环境中的 PyMuPDF 对 16 个 PDF 做只读检查：

- 逐页调用 `page.get_text("text")`；
- 统计整份 PDF 的可提取文字字符数；
- 统计空文字页和含图片页；
- 不保存提取文本，不改写 PDF。

当前系统的 Parser 规则是：整份 PDF 没有可提取文字块时标记 `needs_ocr`。本报告同时采用该规则，避免把本次资产盘点和现有索引口径混淆。

### 5.2 结果

| 指标 | 数量 |
|---|---:|
| PDF 总数 | 16 |
| 打开失败 | 0 |
| 按“整份无文字”规则明确疑似扫描 PDF | 0 |
| 低文本、且页面含图像的人工复核候选 | 2 |
| 存在至少一页无文字、但整份仍有文字的 PDF | 1 |

结论不能写成“没有扫描 PDF”。更准确的结论是：

- 当前 PyMuPDF 能从 16 个 PDF 中提取到文字，因此没有发现符合现有 `needs_ocr` 严格规则的 PDF；
- 其中 2 个 PDF 的整份文字量仅为 8 和 16 个字符，且页面含图像，属于低文本图像型候选，应在 OCR/Document Engine 阶段人工复核；
- 另有 1 个 PDF 存在单个空文字页，但整份文档仍有可提取文字，不能据此将整份文件判为扫描件；
- “页面含图片”不等于“扫描 PDF”，图文混排、导出的演示材料和图纸资料也可能同时含有文字层。
