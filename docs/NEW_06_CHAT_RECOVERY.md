# NEW-06：问答发送与会话恢复

日期：2026-09-28。范围：前端修复、构建、隔离浏览器行为验证，以及经 Owner 明确授权的真实 8010 浏览器联调。8000 未启动；隔离 8010 已停止。

## 调用链与修前证据

唯一日常发送入口是 `AIChat.tsx` 的 `send()`：用户操作 → 本地消息 → `POST /api/v2/query` → 服务端生成 `query_run_id` → 回答显示和反馈入口。原实现先调用 `setMessages`，再由异步 effect 保存本地消息；等待态只存在于组件内存。`loading` 状态尚未更新时，连续点击可重复调用 `send()`。停止、断网被写成普通助手文本，旧请求返回时没有核对当前会话。以上是调用链确认的缺陷或竞态风险；本轮没有把静态推断冒称为修前浏览器复现。

后端目前没有按前端本地请求 ID 查询进行中状态的接口。`query_run_id` 只在成功响应中产生，页面刷新后不能据此声称服务端仍在处理或已完成。

## 修复口径

发送前同步保存用户问题、本地请求 ID 和等待中的回答占位；成功时原位替换，并保存真实 `query_run_id`。刷新后将遗留等待态显示为“结果状态未知，可重试”。失败和停止保留问题草稿及明确提示；重试产生新请求并记录与上一次本地请求的关联，同时提示可能重复发送。发送入口使用同步请求锁，清空或新建会话时中止本页等待并隔离旧响应。部分回答始终显示答案正文，HTTP 失败保持失败状态，不伪装成成功答案。

## 隔离浏览器验收

使用真实构建页面、本机 Chrome 和受控模拟接口检查；模拟接口只返回合成文本。结果与截图保存在本机隔离目录，未上传仓库。

| 场景 | 结果 |
| --- | --- |
| 发送后立即刷新 | 问题和本地请求 ID 保留；显示状态未知；未伪造服务端 `query_run_id` |
| 同一时刻双击发送 | 浏览器只向模拟接口发出 1 次请求 |
| 断网后重试 | 显示失败并保留草稿；恢复网络后重试成功，关联上次本地请求 |
| 停止后重试 | 显示“本页停止等待、服务端状态未知”；重试成功 |
| 新会话时旧请求返回 | 新会话保持空白，不插入旧会话回答 |
| 成功、部分回答、HTTP 失败 | 正文和状态分别显示；部分回答正文可见；HTTP 失败有错误内容和重试入口 |

`npm run build` 通过。以上为受控浏览器场景结果；真实 8010 复验另见下节，两个结果不互相替代。

## 真实 8010 浏览器复验

隔离副本运行提交 `5258804` 的前端，主答模式为 `V1_PRIMARY`。在真实 8010 页面重复检查以上五种会话场景，均通过；成功的 `ANSWERED` 和实际 `PARTIAL_ANSWER` 正文可见，断网错误有明确提示与重试入口。双击同一问题只生成一条服务端运行记录；停止后重试可能生成两条记录，页面如实提示原请求可能已被处理。逐次 `query_run_id` 和截图保存在本机私有验收目录，未上传公开仓库。

验收开始前，原项目的旧服务一度占用 8010。核实无客户端连接且 Owner 确认没有运行任务后，使用项目自带停止脚本结束该残留进程，再启动隔离副本。原项目知识状态文件在隔离服务启动前已因旧服务活动发生变化；不将其宣称为本任务写入。隔离服务结束后，8010 与 8000 均无监听。

技术验收已完成。2026-09-28，Owner 查看刷新与断网提示后回复“提示可用”。这项人工结论确认的是提示文案；浏览器操作由 Codex 执行，不记录为 Owner 亲自操作。NEW-06 至此收口。
