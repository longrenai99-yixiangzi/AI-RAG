## 1. 结论先行

你的判断基本成立，但需要精确表述：

> 当前系统已经读取并解析了一部分文件正文，也已经把大部分支持格式的文本放进了 Shadow Qdrant；但尚未完成逐文件、逐页/段/行/表格单元格的结构化覆盖。因此，系统并不能保证你提出的“某个文件中的某一句或某一行”一定能被检索和回答。

当前主要缺口不是单纯的 Embedding 模型能力，而是知识闭环的粒度和覆盖问题：

1. 外部 Root-002 资料不能自动进入正式知识源；
2. `.doc`、`.xls`、`.ppt` 等旧格式没有进入当前扫描器；
3. 2 个扫描特征 PDF 没有执行 OCR；
4. 1 个 Markdown 模板因 Front Matter 错误没有形成有效 Chunk；
5. XLSX 当前主要按“每个有效 Sheet 一个 SourceBlock”处理，不能精确到数据行和字段；
6. Markdown Chunk 的定位通常覆盖多行，不能保证句子级定位；
7. 正式 Qdrant collection 存在，但当前只读点数为 `0`，当前可验证的主要是 Shadow 索引；
8. Trial 中的 Provider 仍关闭，未命中特殊确定性路径的普通问题可能无法生成回答。

因此，`4747/4747` 的 Metadata 和 location 完整率，只能说明结构字段存在，不能说明每一条业务事实都可检索。

## 6. 内容粒度审计

这是本次最重要的发现。

### 6.1 XLSX：有 Sheet 定位，没有行/字段级覆盖

当前 10 个 XLSX 共形成 12 个有效 Sheet SourceBlock、227 个 Chunk。

只读分析 Shadow payload 后得到：

| 指标 | 结果 |
|---|---:|
| XLSX Chunk | 227 |
| `row_start == row_end` 的精确单行 Chunk | 0 |
| Chunk 最小覆盖行数 | 2 |
| Chunk 最大覆盖行数 | 362 |
| Chunk 平均覆盖行数 | 153.18 |

这说明当前 XLSX 的 `location` 虽然存在，但大量 Chunk 的定位类似：

```text
Sheet1，Row 1-362
```

而不是：

```text
Sheet1，Row 14，字段“施工图设计总工期”，值 332
```

这正是“答案明明在表格某一行，但系统没有命中”的结构性原因。

### 6.2 Markdown：有多行范围，没有稳定句子级定位

当前 Markdown 共 2,495 个 Chunk：

- 只有 169 个 Chunk 的定位范围恰好为单行；
- 平均一个 Chunk 覆盖约 5.16 行；
- 最大一个 Chunk 覆盖 67 行。

因此 Markdown 的文本大部分已经进入索引，但“某一句话”的稳定定位和精确检索仍不充分。

### 6.3 PDF、PPTX、DOCX

- PDF：主要定位到页，页内句子和表格行没有进一步结构化；
- PPTX：主要定位到幻灯片，文本框和表格单元格没有成为独立检索单元；
- DOCX：可以定位段落或表格，但一个 Chunk 可能覆盖多个段落，未形成统一原子事实层。

## 9. 修复优先级建议

### P0：先解决“答案根本进不来”

1. 建立已审批 Knowledge Root 的真实扫描闭环，不再只依赖 Markdown 登记页；
2. 对 `.doc`、`.xls`、`.ppt` 建立明确的只读处理或人工转存策略；
3. 修复 Front Matter 错误文件，不能让模板文件静默成为 Chunk=0；
4. 对 `needs_ocr` 文件建立明确的 `OCR_PENDING` 状态，禁止把低文本页面当作完整正文；
5. 在正式切换前解决正式 Qdrant 点数为 0 的问题。

### P1：解决“正文存在但具体行/句找不到”

1. XLSX 增加 Workbook/Sheet/Header/Row/Cell 结构化记录；
2. Markdown 增加句子级或事实级定位，同时保留标题路径；
3. PDF 增加页内段落、表格行定位；
4. PPTX 增加文本框和表格定位；
5. 让精确字段检索可以绕过普通 Top-K，直接在已确认候选文档内扫描原子证据。

### P2：解决“已经命中但回答路径不稳定”

1. 将直接数值、日期、工期、比例、目标等字段统一纳入 Direct Fact Path；
2. 对“有哪些方案”这类问题使用确定性列表/选项路径；
3. Provider 失败时返回经过引用校验的证据型回答，而不是只显示“生成服务不可用”；
4. 在界面上显示“文件覆盖、行/句覆盖、OCR状态、索引状态”，不要只显示 Chunk 数量。

## 10. 下一步建议

下一步不建议继续针对单个问题添加特判。建议先建立一个“原子证据覆盖层” Shadow 版本：

```text
知识源
→ 文档/Sheet/页/段落/行/字段识别
→ 原子证据记录
→ 精确定位索引
→ Hybrid Retrieval
→ Evidence
→ 确定性事实或 Claim 回答
```

第一批只处理你最常问的三类：

1. Excel 行/字段事实；
2. Markdown/PDF 中的制度条款和单句事实；
3. Word/PPTX 中的项目案例段落和表格。

在此之前，不应宣称系统已经“学习完整个知识库”。
