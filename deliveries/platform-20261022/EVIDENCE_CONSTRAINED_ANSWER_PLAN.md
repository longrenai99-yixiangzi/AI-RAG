# 受证据约束的大模型答复流程：诊断与实施稿

状态：用户已确认实施，简短答复协议已完成代码与离线验证，未部署、未启用默认生成。本文不批准任何资料外发、连续模型调用、收费或正式服务切换。实际变更见[实现与验证记录](CONCISE_IMPLEMENTATION.md)。

## 已核实的直接原因

1. `runtime/app/trial/platform_existing.py` 的日常检索请求固定 `mode: sources`，不会调用回答生成器。
2. `runtime/app/trial/unified_preview.py` 绑定 `UnavailableLLMProvider`，状态接口明确返回 `model_http_enabled: false`。配置里有模型或凭据，不等于该请求链实际用了它。
3. 本轮改造前，`runtime/app/trial/platform_generation.py` 只有 `selection_packet` 要求模型返回原文单元编号与缺口，再由 `render_selection` 回填原文。这个旧协议能限制自由编造，却不能完成精炼改写、跨段组织与直接回答。本轮新增逐项短引文协议，旧预览仍按旧协议处理，未修改原批准内容。
4. `GenerationWorkflow` 按冻结包、单次批准、同日价格和版本检查执行。此前逐批测试的批准不构成后续每道题的自动调用授权；预算和剩余次数不能默认为无限。

## 原因判断

最初为了在现有资料下跑通平台，采用“本地检索先工作、模型单独受控试验”的方式有其阶段用途。但是后续主要通过字段提取和摘录规则修补具体错误，没有完成通用的生成协议与默认路由，这是实现上的缺口。不能把“没有足够资料”当作模型始终没有参与的原因，也不能把模型接通等同于答复可靠。

正文已正确召回却给出整节背景，通常是答案组织缺陷；检索到相关章节但没有所问数值，可能是切片或字段提取缺陷；没有召回正确原文则应先修召回。三者必须分别诊断，避免每次都补解析或每次都让模型猜。

## 建议目标

在批准的数据范围和调用额度内，日常问题默认走“查证据—模型组织短答案—验证—显示引用”。可确定的原生人数、金额、面积及完整表格计算继续由确定性程序取值与运算，模型只组织表达，不能改变已验证数值。证据不足、冲突或所问条件未被支持时，明确说明缺口或请求澄清。

“默认参与”指在已批准策略内自动执行，不等于每道题强制调用。已有有效的同问题、同来源版本审核答案可以复用；明确数值可直接答；只有在需要组织语言且证据足够时调用模型。页面要显示“审核答案 / 本地提取 / 模型基于证据生成 / 证据不足 / 技术失败”等实际状态。

## 请求与回答契约

证据包包含：问题、主体和阶段约束、已验证字段、主证据单元、引用标识、可读文件名、短定位、来源版本。辅助线索不直接作为事实依据。只发送答题所需内容，不发送本机路径、凭据、全库或参考答案；证据文字是数据，不能作为模型指令。

模型按下列结构返回，前端不直接展示未验证原始文本：

```json
{
  "status": "ANSWERED",
  "claims": [
    {"text": "示例项目配置示例岗位1人。", "evidence_ids": ["E1"], "support_quotes": ["示例岗位：1人"]}
  ],
  "gaps": []
}
```

该示例是合成数据。短引文必须能在指定同版本证据中找到；引用存在只是必要条件，不证明整句主张被支持。程序能验证编号、来源、字面数字与明确范围，不能通用判定自然语言蕴含。对身份、阶段、专兼职、条件、例外等不能可靠验证的自由改写，要缩回已验证原文表达，或标明待核，不得以另一次模型自评冒充事实证明。

主张级验证后再用后端拼装答复和引用。单字段题默认一到两句，列举题先答所问条目及必要条件，原文细节放引用展开。不使用简单字数截断丢掉限定词；不靠题目编号或固定参考答案制造通过。

## 执行顺序与回退

1. 留存问题并去重，检查资料准入、来源版本及授权策略。
2. 混合召回、范围约束与重排；构造主证据，检查问题所需内容是否覆盖。找不到不发送；只找到背景不当作主证据。
3. 有有效审核答案则复用；确定性字段直接取值；需要组织表达时，在已批准范围和预算内执行一次模型调用。
4. 解析与主张验证；失败时保存原响应与原因，不自动追加收费修复调用。可回退到有明确标签的本地已验证摘录。
5. 保存最终答复、证据版本、验证结果、调用及耗时；来源更新后缓存失效。前端展示短答案和可追溯引用。

预算预占必须在发送之前原子记账；并发、超时和重复提交不得绕过次数或金额上限。超时结果标记“调用结果未确认”，未经对账不自动重发。源文件变化或证据过长则重新检索/缩小问题，不能沿用旧批准包。

## 验收与停止条件

- 合成检查：无证据编造、跨项目、错阶段、数字单位变化、否定与例外丢失、只答部分、提示词注入、伪造引用、版本变化、重复与并发消费、失败与超时。
- 离线检查：复用历史模型响应验证协议；协议或提示词改变后，历史回放不能替代真实生成效果验证。
- 小批真实生成：先形成可审阅的实际请求、授权次数、预算及价格依据；用户批准后才外发。不把此前已用完的授权沿用到新批次。
- 独立业务新题：用户核对答复是否精确、范围是否正确、引用是否支持全部主张，单列失败和无法回答；不将“HTTP成功 / JSON正确 / 引用可打开”计为业务通过。
- 任一未授权外发、预算突破、错误主体借值或无依据事实，停止默认生成；保留检索及有标签的本地摘录，排查后再验证。
